# Factory ERP Architecture

## 目录结构

```text
backend/   统一后端 API 服务，负责认证、权限、业务规则、数据校验和持久化
web/       Web 管理端，通过后端 API 进行数据读写
desktop/   Windows 桌面端，通过后端 API 进行数据读写
mobile/    Android 移动端，通过后端 API 进行数据读写
docs/      需求说明、数据库设计、接口文档和架构记录
```

## 核心原则

后端 API 是唯一数据源。Web、Windows 桌面端和 Android 移动端都必须通过同一套 API 读写数据，不允许任何客户端直接访问数据库或维护独立的权威业务数据。

## 推荐逻辑架构

1. **客户端层**：Web、Desktop、Mobile，仅负责展示、交互、轻量缓存和调用 API。
2. **API 层**：统一认证、授权、参数校验、响应格式、错误处理和限流。
3. **业务层**：按用户权限、材料入库、订单录入、工序流转、报表分析划分模块。
4. **数据层**：数据库、对象存储、消息队列和缓存等基础设施，由后端统一访问。
5. **审计与监控**：所有关键写操作记录审计日志，并暴露可观测性指标。

## 多端一致性策略

- 所有写操作先提交后端，由后端完成事务、校验和状态变更。
- 客户端展示的状态必须来源于后端查询或后端确认后的响应。
- 如需要离线能力，应使用待同步队列，并在恢复网络后由后端进行冲突检测。
- 报表统计以后端聚合结果为准，避免各端自行计算导致口径不一致。
